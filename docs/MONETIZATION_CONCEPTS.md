# Концепции монетизации Bridgik

Документ объединяет **5 отобранных продуктовых способов монетизации** сервиса Bridgik. 
Все концепции строго соблюдают фундаментальные принципы продукта:
1. **Никакой принудительной регистрации** (нет связки с email, паролями и сбором персональных данных).
2. **Базовый прямой P2P остаётся 100% бесплатным и безлимитным** (нулевая стоимость передачи для сервера, максимальная виральность).
3. **Оплата за реальную ценность:** за решение технической проблемы, за безопасность или за сэкономленное время.

## Концепция 1: «Оставить в шлюзе» (Асинхронный мост / Drop & Go)

### 1. Проблема и боль пользователя
Классический WebRTC P2P требует, чтобы оба устройства одновременно держали открытыми вкладки браузера. Если получатель офлайн, в дороге или спит, отправителю приходится держать ноутбук включенным и ждать.

### 2. Пользовательский сценарий (UX / Flow)
1. Отправитель выбирает файлы любого размера и переключает режим: **«Прямой P2P (онлайн)»** → **«Оставить в шлюзе на 24 часа»**.
2. Браузер шифрует файлы на стороне клиента (ключ шифрования зашит только в ссылку/PIN).
3. Зашифрованный блоб временно загружается на сервер.
4. Отправитель получает ссылку/PIN, **закрывает браузер и выключает компьютер**.
5. Получатель переходит по ссылке в удобное время, скачивает файл, после чего файл **моментально физически удаляется с диска** (или автоматически стирается таймером через 24 часа).

### 3. Техническая реализация
- **Шифрование:** Web Crypto API (AES-GCM 256 бит). Ключ шифрования находится в URL-хэше (`#key=...`), который браузер никогда не отправляет на сервер (Zero-Knowledge). Сервер хранит лишь нечитаемый бинарный слепок.
- **Хранилище:** Временный диск / NVMe-кэш или S3 с политикой Lifecycle на удаление через 24 часа.
- **Самоуничтожение:** Webhook или сокет-событие после успешного `HTTP 200` завершения загрузки удаляет файл с диска.

### 4. Модель оплаты
- **1 бесплатный шлюз в неделю** для каждого посетителя (активация и тест удобства).
- **Микроплатеж:** 29–49 ₽ за разовую выгрузку (СБП / карта / эквайринг в 1 клик).
- **Пакет ключей:** 10 шлюзов за 199 ₽ (анонимный токен сохраняется в `localStorage`).

## Концепция 2: Bridgik как Telegram Mini App (TMA)

### 1. Проблема и боль пользователя
В Telegram лимит на размер файла составляет 2 ГБ (для Telegram Premium — 4 ГБ), а скорость скачивания крупных архивов часто падает до 1–2 МБ/с. При этом в Telegram уже решена главная проблема конверсии — есть нативная валюта **Telegram Stars**, позволяющая оплачивать услуги в 1 тап по Face ID / отпечатку без ввода реквизитов карт.

### 2. Пользовательский сценарий (UX / Flow)
1. Пользователь запускает бота `@bridgik_bot` и нажимает кнопку «Открыть Bridgik».
2. Сервис запускается прямо внутри Telegram через WebApp.
3. Профиль, ник и Telegram ID подтягиваются автоматически (нулевая регистрация).
4. Отправитель может передать файл любого размера (10–50+ ГБ) напрямую другу по P2P-каналу на полной скорости домашнего интернета.
5. Бот может отправить уведомление получателю прямо в чат Telegram: *«Вам отправлен файл через Bridgik! Нажмите для скачивания»*.

### 3. Техническая реализация
- Telegram WebApp SDK (`window.Telegram.WebApp`).
- Идентификация сессии через валидацию `initData` (HMAC SHA-256 с бот-токеном) без создания классических паролей.
- Telegram Stars Payments API (`createInvoiceLink` / `openInvoice`).

### 4. Модель оплаты
- Оплата любых платных опций (шлюз, постоянные связки, пробив сетей) списывается в Telegram Stars (10–30 Stars за операцию).
- Конверсия в Telegram в 3–5 раз выше, чем на внешних сайтах с эквайрингом.

## Концепция 3: «Sticky Bridge» — Постоянная связка своих устройств

### 1. Проблема и боль пользователя
Огромный процент пользователей Bridgik использует сервис для себя: быстро перекинуть фото, скриншот из буфера, ссылку или файл между своим телефоном (iOS/Android) и рабочим компьютером (Windows/Mac).
Но сейчас каждый раз при открытии вкладки приходится сканировать QR-код или вводить 6-значный PIN. Для регулярного использования 5–10 раз в день это создает лишнее трение.

### 2. Пользовательский сценарий (UX / Flow)
1. В интерфейсе появляется кнопка: **«Связать мои устройства навсегда»**.
2. Сервис генерирует уникальную секретную мнемоническую фразу из 4 слов (например, `cyber-dino-sky-bridge`) или QR-код сопряжения.
3. Пользователь вводит фразу на втором устройстве **один раз**.
4. Теперь, где бы ни находился пользователь (телефон на 4G в метро, ноутбук на домашнем Wi-Fi), при открытии Bridgik устройства **автоматически видят друг друга онлайн**.
5. Появляется постоянный персональный канал: перетащил файл на ПК — он мгновенно появился на телефоне. Скриншот из буфера улетает в один клик.

### 3. Техническая реализация
- **Криптографическая пара ключей:** При генерации фразы в браузере создаётся пара ключей Ed25519 / Web Crypto.
- **Аутентификация без БД пользователей:** Устройства подписывают временный timestamp своим приватным ключом. Сигнальный сервер проверяет подпись и объединяет девайсы с одинаковым публичным идентификатором связки в закрытый WebSocket-рум.
- Хранение ключа — локально в `IndexedDB` браузера.

### 4. Модель оплаты
- **Lifetime-покупка навсегда:** 199–299 ₽ (или 100–150 Telegram Stars).
- Плата разовая: пользователь получает персональный «AirDrop между любыми несовместимыми операционными системами».

## Концепция 4: Спасение в закрытых сетях («Turbo-пробив» / NAT Bypass)

### 1. Проблема и боль пользователя
В 15–20% реальных ситуаций WebRTC P2P **технически не может установить прямое соединение**:
- Строгий корпоративный Wi-Fi в офисе со сложными правилами безопасности (Symmetric NAT).
- Гостевые сети отелей, аэропортов, больниц, университетских кампусов.
- Мобильные сети некоторых операторов с изоляцией абонентов (CGNAT).
В этот момент обычный бесплатный P2P зависает со статусом «Сбой подключения», а пользователь уходит ни с чем.

### 2. Пользовательский сценарий (UX / Flow)
1. При попытке передачи система обнаруживает блокировку прямого соединения (ICE connection failed / Symmetric NAT).
2. На экране появляется четкое и честное сообщение:
   > *«Файрвол вашей сети блокирует прямое соединение между устройствами. Включить Turbo-пробив через защищённый высокоскоростной шлюз?»*
3. Пользователь нажимает одну кнопку (оплата 19–29 ₽ или 10 Stars).
4. Соединение моментально восстанавливается через выделенный высокоскоростной сервер-ретранслятор (Turbo Relay). Файл успешно передаётся.

### 3. Техническая реализация
- Автоматическая диагностика ICE Candidate types (обнаружение невозможности установления `host` или `srflx` соединения).
- Динамическая выдача временных TURN-credentials (REST API для `coturn` с ограничением по времени жизни токена — 1 час).
- Сервер работает чисто как ретранслятор зашифрованных UDP-пакетов (DTLS-SRTP), не расшифровывая и не сохраняя файлы.

### 4. Модель оплаты
- **Микроплатеж за результат:** 19–29 ₽ за 1 сессию передачи.
- **Пакет:** Pro-доступ к Turbo Relay на месяц за 149 ₽ для тех, кто часто работает в офисах или отелях.
- Пользователь платит именно в момент острой проблемы, когда альтернативы нет.

## Концепция 5: Шпионский режим / Параноик-передача (Burner Transfer)

### 1. Проблема и боль пользователя
Передача критически важных и конфиденциальных данных: сканов паспортов, документов, криптографических seed-фраз, ключей доступа, NDA-отчетов, баз данных или финансовых таблиц.
Отправляя такие файлы через Telegram или облако, пользователь рискует: файл навсегда оседает в истории чата, на серверах компании, либо получатель может забыть удалить его с общего компьютера.

### 2. Пользовательский сценарий (UX / Flow)
Отправитель переключает тумблер **«Режим Параноик (Burner)»** и настраивает параметры безопасности:
1. **Одноразовое скачивание (One-Shot):** ровно 1 успешная загрузка. В момент завершения скачивания ссылка мгновенно сгорает навсегда.
2. **Таймер самоуничтожения:** *«Удалить файл через 60 секунд после первого открытия»*.
3. **Уничтожение при закрытии вкладки:** файл держится только в оперативной памяти браузера получателя; как только вкладка закрыта — файл бесследно исчезает.
4. **Защита от перебора PIN (Kill-Switch):** если кто-то ввёл неверный PIN-код 3 раза подряд — файл немедленно стирается и аннулируется.
5. **Динамический водяной знак:** на предпросмотре документов полупрозрачно накладывается IP-адрес получателя, дата и время (защита от утечки через фото/скриншот экрана).

### 3. Техническая реализация
- Шифрование на клиенте: Web Crypto API (AES-256-GCM).
- Хранение ключа расшифровки: ключ передается только в URL hash фрагменте и уничтожается из DOM после первой инициализации.
- Механизм Kill-Switch: бэкенд отслеживает число неверных попыток авторизации сессии и при превышении лимита посылает команду уничтожения шифротекста.

### 4. Модель оплаты
- Разовая покупка: **49–99 ₽** за одну «Шпионскую посылку» или **25–50 Telegram Stars**.
- Целевая аудитория (юристы, криптоинвесторы, предприниматели, бухгалтеры) крайне чувствительна к рискам и с готовностью оплачивает гарантированную приватность.
